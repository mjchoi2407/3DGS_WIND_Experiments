# P3 잔진동·움직임·계산 비용 탐색

## 현재 상태

- 후속 사용자 관찰에서 추천안의 wind2.8초 잔진동이 남았다. [바람 시간 평활·국소화 비교](wind_field.md#현재-상태)에서 사용자는 시간 평활 바람을 후속 외력 기준으로 선택했다. 아래 감쇠 추천과 당시 수치는 유지한다.

- 2026-10-01 완료: 직접 GPU 선별·세 감쇠 계열 비교·계산 최적화·유망안 전체wind 검증을 수행했다. **추천1안은 막5ms + 굽힘20ms + 기하량 재사용**이다.
- 사용자 선호인 P3 굽힘 강성 1/500, 전역 감쇠 0, 기본64/조건부128, 정밀도·허용오차·기존 접촉/독립 검산/rollback을 유지했다.
- 공통5초 raw→wind5초 300/300 완료: 빠른 위치/법선 진동 48.4%/56.5% 감소, 큰 동작 99.4%·속력 95.3% 유지, dt/2 복구 0회다.
- 같은8초 raw의2초 비용 대조: 기준64.74분→추천35.93분,44.5% 단축. 같은 굽힘20ms의 기하 재사용 전후는65.40→35.93분,45.1% 단축이다.
- 기하 재사용 전후120프레임의 최대 위치 차이2.22e-16m·속도 차이4.13e-14m/s. 전체 비트 동일은 아니며 반올림 수준 차이다.
- [최종 표·그래프](../../artifacts/runs/p3_self_contact/vibration_search_20260930_01/index.html), [추천·근거hash](../../artifacts/runs/p3_self_contact/vibration_search_20260930_01/recommendations.json), [검증 목록](vibration_search_checks.json)이 대상과 수치를 식별한다.
- 7조건×두 상태의 짧은 비용 선별,기준과 세 계열의 120프레임, 캐시 동일성 120프레임, 추천안 wind 300프레임을 완료했다. 실패·미선정 분모는 보존한다.
- CPU 회귀·실제 상태 GPU-NumPy 독립 oracle·raw/외력/시간/핀/감쇠장부 검산 통과. 정확한 검증 묶음과 중복 수는 검증 목록을 따른다.
- 막10ms는 개선 대비 비용 증가,약한 전역1은 큰 움직임 둔화로 추천하지 않는다. 범위가 큰 적분기/표현 교체는 제외했다.
- 기본 API의 5ms 한도·조합 금지는 유지하며, 선정안은 별도 동결 진단 context에서만 활성화한다. 학습 기본값이나 canonical 방법을 변경하지 않았다.
- 사각형 1813노드·GTX1080Ti·공통5초 이후의 검증이다. 다른 씬/GPU, 새 조건의 시간·공간 수렴, 학습 적격성은 미판정이다. 60Hz 기록의 30Hz 초과 alias도 미분리다.
- 재생 스크립트로 기준/추천안의 wind·tail을 연결했다. 렌더 확인과 사용자의 주관적 시각 채택은 구분한다.
- code·experiments 기존 dirty·원본·실행을 보존했다. commit/push/fetch 없음. 웹 원문 조회 외 외부 패키지 다운로드·설치 없음. R1 제한 CG 경계를 확인했고 TeX/PDF는 변경하지 않았다.

## 최종 추천과 비교

전체 천의 속도를 직접 줄이는 대신, 빠르게 굽힘이 변하는 성분에 내부 감쇠를 주는 안이 가장 균형이 좋았다. **막 감쇠 5ms 유지 + 굽힘 감쇠 20ms + 전역 감쇠 0**을 선택한다. 여기서 ms는 재료 감쇠 시간계수이며 적분 dt가 아니다. 같은 평가 상태의 기하량을 반복 계산하지 않도록 구현을 개선해 비용도 낮췄다.

| 조건 | 위치 진동 감소 | 법선 진동 감소 | 큰 동작 유지 | 계산 시간 | 판단 |

## 비교 재생

프로젝트 루트에서 아래 명령으로 완료된 결과를 재생한다. 왼쪽 하늘색은 기준, 오른쪽 금색은 추천안이다. 시뮬레이션을 다시 실행하지 않는다.

```bash
bash experiments/R1_teacher_velocity_reset/self_contact/view_gpu_vibration_search.sh --stage wind
```

같은 8초에서 분기한 2초 비교는 `--stage tail`을 쓴다. 뷰어는 원시 결과 hash·핀·시간·외력·장부를 확인한 뒤 FP32 표시 캐시를 만든다. 분석은 FP64 raw hi+lo를 사용한다. [wind 렌더](../../artifacts/runs/p3_self_contact/vibration_search_20260930_01/viewer_wind_t4p2.png),[tail 렌더](../../artifacts/runs/p3_self_contact/vibration_search_20260930_01/viewer_tail_t1p2.png)는 두 표면이 표시되는지 확인한 근거이며 애니메이션의 주관적 선호 판정은 아니다.

## 실험 조건과 선별

기존 사각형1813노드, 굽힘1/500, 기본64/조건부128, GPU 접촉·기하·힘/에너지·시간 검산·rollback을 유지한다. 같은 GTX1080Ti에서 순차 측정한다.
각 후보는 원본8초와9.5초 raw hi/lo에서 각각6프레임을 독립 시작한다. 같은 시점 기준을 함께 재실행해 다른 때의 GPU 부하를 속도 차이로 오인하지 않는다.
유망 후보만 같은8초 raw에서8–10초120프레임을 계산한다. 상태/바람을 초기화하지 않고 원본 외력 구간을 절단한다.
phase_time_s는 원래wind 시간(start-5초+경과), trajectory_time_s는 전체 시간이다.

선별 목표는 빠른 위치 성분 약30% 감소와 큰 움직임 유지, 시간 증가 약30% 이내다. 참고선이며 새 연구 합격 기준이 아니다.
비용이50% 이상 증가하는 후보는 효과가 특별히 좋지 않으면 확대하지 않는다. 실패·예산 종료는 분모와 증거를 보존한다.
2초의0.2–3/3–10/10–30Hz 위치 성분·원시2차 차분·속력·끝점 움직임을 공통512점에서 함께 비교한다. 화면의 떨림을 보조 평가하기 위해 같은 P3 재생 삼각형의 단위법선에도 같은 주파수 분석을 적용한다. 법선 성분의 degree 표기는 작은 각도 근사이며 물리 합격 기준이 아니다. rest 면적 가중을 고정하고 저장 raw에서 계산하여 시뮬레이션 비용을 추가하지 않는다.60Hz 저장의30Hz 초과 alias와 감쇠 전환 반응을 원인 판정으로 확대하지 않는다.

## 실행과 원본

새 [실행기](../../../code/wind3dgs/evaluation/teacher_gpu_vibration_search.py)의 `prepare`, `force_oracle`, `worker`, `summarize`가 입력·독립 대조·실행·상태를 관리한다.
`--action prepare`는 새bundle만 생성하고, `--action oracle --case NAME` 뒤 `--action run --case NAME --stage cost8|cost95|tail`로 진행한다.
기존 bundle/log/output을 덮어쓰거나 실패 run을 자동 재개하지 않는다. 실패 후보와 독립적인 다음 후보의 시험은 별도 결과로 남긴다.

## 기준120프레임 재현

새 기준8–10초는120/120 완료,실제 frame wall3884.40초(64.74분),기존과 같은1회 dt/2 복구다. [전체 원본 대조](../../artifacts/runs/p3_self_contact/vibration_search_20260930_01/reference_full_equivalence.json)는38프레임 raw 비트 동일,나머지의 최대 위치 차이2.33e-15m·속도 차이3.38e-12m/s를 기록한다. 전체 비트 동일을 주장하지 않으며 CG 움직임과 진동 지표는 동일 수준이다. [분석 원본](../../artifacts/runs/p3_self_contact/vibration_search_20260930_01/analysis_tail_01/report.json)의 `cases.reference`가 후속 후보의 같은 GPU 비용·효과 기준이다. 원본 당시67.65분을 새 후보 비용의 분모로 혼용하지 않는다.

## 굽힘20ms 마지막2초 결과

[같은8초 raw에서120/120 완료한 비교](../../artifacts/runs/p3_self_contact/vibration_search_20260930_01/analysis_tail_02/report.json)의 `cases.bend20`은10–30Hz 위치 성분37.97%,단위법선 성분46.36%,원시 위치2차 차분 RMS21.41% 감소다. 큰 동작 RMS94.50%,속력94.93%,0.2–3Hz 위치 성분95.79%를 유지했다. 마지막1초에서는 빠른 위치/법선 성분55.92%/62.39% 감소해 초기 전환 구간만의 개선은 아니다.

실제 wall65.40분 대 새 기준64.74분으로+1.02%다. 굽힘20ms는 추가 dt/2 복구 없이120프레임의 기존 검산을 통과했다. 두 짧은 상태의+24% 비용을 전체 구간에 외삽하지 않는다.

큰 변형 피크는9.15초로 같고 위치2차 차분 최대값5.19→5.17mm로 거의 유지된다. 순간적인 큰 휨까지 제거한 결과나 진동이 완전히 없어진 결과로 해석하지 않는다. [PSD·시간 그래프](../../artifacts/runs/p3_self_contact/vibration_search_20260930_01/analysis_tail_02/motion.png)를 확인했으며,다른 감쇠 계열·기하 재사용·공통5초부터wind5초 비교까지 완료했다. 최종 판단은 위의 전체wind 검증을 함께 따른다.

## 막10ms 마지막2초 결과

[막10ms120/120 완료 분석](../../artifacts/runs/p3_self_contact/vibration_search_20260930_01/analysis_tail_03/report.json)의 `cases.mem10`은 빠른 위치 성분10.66%,단위법선 성분8.60%,원시 위치2차 차분 RMS6.62% 감소다. 큰 동작98.92%·속력98.90%를 유지하나 실제 wall74.48분으로 기준 대비+15.04%,dt/2 복구2회다. 기존 검산을 통과했으며 실패 시도·복구 비용을 포함한다.

움직임 보존은 좋지만 굽힘20ms보다 진동 감소가 작고 비용이 커서 현재 우선 후보에서 제외한다. 막20ms는 앞선 짧은 비용 선별에서+78%여서 확대하지 않았다. 기존 막5ms를 없애야 한다는 결과가 아니며,추가 감쇠의 우선 대상은 굽힘이다. 전역1 조합과 기하 재사용·전체wind 결과는 해당 절에 기록했다.

## 약한 전역1 조합 마지막2초 결과

[막5ms+전역1 s^-1의120/120 완료 분석](../../artifacts/runs/p3_self_contact/vibration_search_20260930_01/analysis_tail_04/report.json)의 `cases.global1`은 빠른 위치 성분31.46%,단위법선 성분28.88% 감소이고 wall54.32분으로 기준보다16.09% 짧다. 다만 큰 동작87.53%·속력84.44%만 유지하고 마지막1초의 큰 동작72.51%·속력76.66%로 더 둔해진다. 복구 없이 기존 검산을 통과했다.

현재 목적에서는 굽힘20ms가 진동 감소와 움직임 보존에 더 유리하다. 전역1의 둔화 때문에 전역2의 긴 구간 비교는 확대하지 않았다. 전역2의 완료 근거는 두 짧은6프레임 구간으로 제한한다. 굽힘20ms를 선택했고 계산 재사용과 공통5초부터wind5초 검증까지 완료했다.

## 비용 증가의 관찰 근거

[짧은 비용 분해](../../artifacts/runs/p3_self_contact/vibration_search_20260930_01/short_cost_breakdown.json)의 `gmres_total`은 기준82,860회,막20ms143,282회다. 막20ms의 반복 증가 약73%와 wall 증가 약78%가 함께 관찰된다. 굽힘20ms는29,707회로 반복을 줄이지만 wall은 약24% 증가한다. 굽힘 접선의 반복당 비용이 더 크다는 해석과 부합하며 계수와 wall의 단조 관계를 가정하지 않는다. 접촉 시간은 각 조건 wall의 약2–3%였고 이미wall에 포함된다. 이 두 짧은 구간을 전체wind 또는 모든 접촉 상태의 병목 판정으로 확대하지 않는다.

반복수는 실행별 마지막 누적값의 합이다. 최초 집계의 프레임별 누적값 중복 합산을 정정했으며 실제 wall·선별 결과는 바뀌지 않는다. `active_linear_cycles`는 실제 실행 횟수가 아닌 정책값이라 성능 합계에 사용하지 않는다.

## 정확한 굽힘 HVP 비용 최적화 후보

기존 `BendingDamping.hvp`는 같은 평가 상태에서 접선 방향만 달라져도 힘을 재조립하고 소산 합계를 반복 축약한다.
별도 `FastBendingDamping`은 기존 점별 정확한 방향 미분을 유지하고 접선만 같은 순서로 조립한다. 힘·총 소산은 직전 evaluate의 소유 버퍼를 보존한다.
속도 갱신은 유효성을 지우고 새 evaluate가 없는 HVP는 GPU 상태122로 거절한다. 독립 검산의 evaluate는 그대로이며 solver 버퍼를 공유하지 않는다.
기본 구현은 변경하지 않고 실험 context의 `fast_bending_hvp=True`에서만 선택한다.

CPU의 두 고정 경계 조건·두 상태·여러 방향·두 dt의 접선은 기존과 비트 단위 일치했다. 원본/최적화19개 CPU 검사와 최종2개 재검사가 통과했다.
[별도 동결 묶음](../../artifacts/runs/p3_self_contact/vibration_search_20260930_01/bundle_fast/)에서 기존 GPU 선별 종료 후 HVP 비용과 같은6프레임 궤적을 비교했다.
GPU의 두 실제 상태·네 방향에서 원본과 비트 단위 일치하고 HVP 자체 비용은 약2% 감소했다. 전체12프레임 비용은 약1.8% 감소했지만9.5초 상태의 raw는 최대9.33e-15 차이로 비트 동일 검사를 통과하지 않았다. 물리 검산 실패는 아니며 차이는 시각적으로 의미 있는 수준이 아니다. 작은 비용 이득과 추가 구현 부담을 고려해 단독 추천에서는 제외했다. 이 접선 전용 조립은 후속 기하 캐시 구현의 기반으로 사용했다. [대조 원본](../../artifacts/runs/p3_self_contact/vibration_search_20260930_01/fast_frame_comparison.json)의 failed는 비트 동일 판정이다. `screen_driver.py`→`fast_driver.py`→`tail_driver.py`는 이 탐색 디렉터리의 독립 실행이며 같은 GPU에서 겹치지 않도록 선행 종료를 기다린다.
새 비용 구간은30분, 새120프레임 작업은2시간 예산을 적용한다. 초과 시 이 탐색이 생성한 해당 process group만 종료하고 증거를 보존한다. 기존 사용자 작업은 중단하지 않는다.

## 같은 평가 상태의 기하량 재사용 후보

2026-10-01: 접선 전용 조립만으로는 약2% 이득에 그쳐, 반복마다 다시 수행하던 raw hi/lo의 보상 합산 결과를 evaluate에서 한 번 보존하는 두 번째 후보를 추가했다. [기하 재사용 구현](../../../code/wind3dgs/teacher/resident_bending_damping_cached.py)의 `CachedBendingDamping.evaluate/hvp`, `cached_fields`는 방향 미분·물성식·FP64 정밀도·힘/소산 evaluate를 유지한다. 새 위치/속도 평가마다 캐시를 갱신하고 속도 갱신 뒤 evaluate가 없으면 상태122로 거절한다.

[CPU 접선·상태 소유 검사](../../../code/tests/test_bending_damping_fast.py)의 두 경계 조건·두 상태·여러 방향·기본/반 dt 대조를 포함해 관련 CPU24개 검사가 통과했다. [별도 묶음](../../artifacts/runs/p3_self_contact/vibration_search_20260930_01/bundle_cached/)의 `cached_bending_hvp=True`에서만 활성화한다. GPU 두 실제 상태·여러 방향의 접선은 원본과 비트 단위 일치하고 독립 oracle도 통과했다. HVP 단위 비용 비율은 약0.0934(약10.7배 가속)지만 전체 프레임/궤적 가속률이 아니다. 실제12프레임·120프레임 비용 대조도 통과했다. [후속 실행 기록](../../artifacts/runs/p3_self_contact/vibration_search_20260930_01/cached_events.jsonl)에서 완료 상태를 확인한다.

`cached_driver.py`는 기존120프레임 후보 비교 종료 후 같은 GPU에서 순차로 oracle·HVP·6+6프레임을 대조한다. 비용이10% 이상 줄고 굽힘20ms의 움직임/진동 효과가 확인될 때만 같은120프레임을 추가한다. 비트 동일 여부와 무시 가능한 roundoff 차이를 별도로 남기며 기존 solver 허용오차를 바꾸지 않는다. 실패·효과 없는 경우 확대하지 않는다.

## 검토한 방법과 범위

변형 속도 기반 내부 감쇠는 [Baraff–Witkin SIGGRAPH1998](https://www.cs.cmu.edu/~baraff/papers/sig98.pdf)의 관련 개념을 참고한다. 현재 구현은 프로젝트의 P3 막·곡률·접힘 속도 법칙이며 해당 논문의 구현을 그대로 사용한 것은 아니다.
적분기 교체와 P3→P1/XPBD 전환은 접촉·검산·움직임까지 함께 바뀌므로 이번 우선 탐색에서 제외한다. 계수 변화와 작은 조합으로 효과/비용을 확인했고, 목표에 부합하는 추천안을 확보해 추가 탐색을 종료했다.
