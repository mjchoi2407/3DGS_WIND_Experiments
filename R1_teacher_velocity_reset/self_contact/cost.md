# 셀프 컬리전 추가 비용: 저장 결과 대조

이 문서는 최적화 전 **v2의 과거 관측 비용**이다. 수치와 당시 실패 분모를 보존한다.
후속 중복 제거·메모리 절감과 공유 GPU 부하로 보류한 최종 성능 판정은 [v3 성능 점검](performance.md)을 따른다.
현재 같은 실행기의 통제된 비용과 실제 초기v1 재측정은 [유휴 조건 보고](idle_performance.md)를 따른다.
사용자는 최초 측정에도 부하가 있었을 가능성을 확인했으며, 아래 과거 배수를 순수 접촉 비용으로 채택하지 않는다.

## 결론과 비교 한계

2026-09-22 사용자 요청에 따라 GPU 본 실행을 종료했다. **이번 비용 정리에서는 새 GPU 계산을 하지 않았다.**
이전 GPU ON/OFF의 같은 초기 중력 프레임은 관측상2.58~7.57배, 직사각형의 같은70프레임 prefix는
3.34배였다. 접촉 후보·시간 CCD·독립 접촉 검산이 추가된 현재 경로는 비용 증가가 크다.
다만 **순수 셀프 컬리전 증가율은 아직 확정하지 못했다.** 다른 날짜/시점의 실행이며,
ON 측정 중 다른 GPU 부하가 관측됐고 프레임 실행기·그래프도 달라 통제된 A/B 벤치마크가 아니다.

원시 수치·계산식·입력/결과/source SHA-256은 [비용 JSON](cost_report.json)이 소유한다.
기존 입력 hash·GPU 종류·dt·물성·공식 허용오차는 대조했고, 바람의 rest 시작 smoke를
기존 preload 이후 wind 궤적과 비교하는 잘못된 분모는 제외했다. RTX5070 비교 근거는 없다.

## GPU: 같은 초기 중력 프레임

GTX1080Ti, FP64 hi/lo Newmark, dt1/3840초, 프레임당64단계.
같은 평면 rest/속도0에서 같은 중력을 가하는 첫 프레임이다. OFF에서 Gauss/절반 dt 재시도는0회다.
아래는 **풀이+독립 검산**이며 준비/컴파일·파일 저장은 제외한다.

| 씬 | 기존 OFF | 새 ON | 관측 추가 시간 | 관측 배수 / 증가율 |
| --- | ---: | ---: | ---: | ---: |
| 직사각형 | 1.734s | 13.117s | +11.384s | 7.57배 / +656.5% |
| 손수건 | 1.283s | 3.428s | +2.146s | 2.67배 / +167.3% |
| 삼각 깃발 | 1.207s | 3.111s | +1.904s | 2.58배 / +157.8% |

세 첫 프레임의 기존/신규 solver 카운터 첫16개도 일치한다. 즉 여기서는 반복 횟수 증가가
관측 차이를 설명하지 않는다. 모두 비접촉 연결 시험이며, 충돌이 없어도 탐색·CCD 비용은 든다.
ON의 프레임 실행기 준비는 각각4.993/3.668/2.099초였고 별도 초기 접촉 준비 비용은 포함하지 않는다.
현재 기록만으로 setup 증가량이나 전체 cold-start 비용을 분리할 수는 없다.

### 직사각형의 저장 완료70프레임

같은 preload 첫70프레임(4,480단계, 물리 시간1.167초)을 대조했다.

| 지표 | OFF | ON |
| --- | ---: | ---: |
| 풀이+검산 합계 | 125.573s | 418.923s |
| 프레임 평균 | 1.794s | 5.985s |

관측 추가 시간293.350초, **3.34배(+233.6%)**다. ON의 프레임 시간은3.914~13.748초로 크게 흔들렸다.
동시 GPU 부하와 실행기 차이를 포함하므로 이 배수를 전체 wind 구간 비용으로 외삽하지 않는다.
ON의 누적 카운터를 프레임별 차분해 비교하면 GMRES 반복/행렬 재구축 횟수는 OFF와 같다.
저장 외력은 정확히 같고, hi 위치 최대 차이1.52e-16m·hi 속도4.72e-12m/s 이하다.
양쪽 저장 검산은 전부 flag0이다. 중단 prefix이며 전체 preload/시뮬레이션 완주 근거는 아니다.

**이70프레임과 세 초기 프레임의 정밀 기하 세분화는0회**였다. 위 비용을 새 영역 세분화 연산
때문이라고 설명할 수 없다. 검사 준비·분기 비용은 남지만, 주요 접촉 단계별 기여율은 미계측이다.

## 실제 접촉 샘플에서 측정한 절대 비용

GPU v2 면/엣지/고속×k1,000/10,000의6사례는8~12단계의 짧은 국소 표본이다.
풀이+검산은 단계당57.94~70.00ms, 독립 검산은 이 합계의21.1~27.1%였다.
이는 shell 계산도 포함한 **전체 절대 비용**이지 접촉만의 증가량이 아니다.
해당 GPU 표본에는 같은 조건으로 측정한 GPU OFF 시간이 없으므로 증가율을 계산하지 않는다.

CPU 기준에는 OFF/ON 비교가 있다. k1,000, 같은 초기 입력/시간 분모의 **CPU 풀이만** 보면:

| 사례 | OFF | ON LBVH | 관측 배수 |
| --- | ---: | ---: | ---: |
| 면 접근60단계 | 0.199s | 1.480s | 7.45배 |
| 엣지 접근60단계 | 0.192s | 1.506s | 7.83배 |
| 고속 접근12단계 | 0.038s | 0.406s | 10.69배 |

CPU 사후 검산은 제외했다. 특히 OFF의 침범 경로에 적용한 개발용 CCD 진단 시간은 운영 OFF 비용이 아니다.
OFF는 그대로 통과하고 ON은 반발하므로 이후 움직임·비선형 반복도 달라진다.
이 CPU 배수를 GPU의 추가 비용으로 옮겨 쓰지 않는다. 원본 기하 판정 범위는 [초기 CPU 보고](README.md)를 따른다.

## GPU 메모리: 명시적 주요 배열의 추가량

v2 접촉 풀이와 독립 검산이 각각 `GPUShellContact`를 갖는다. 후보마다12×12 FP64 Hessian을
미리 확보한다. 현재 `active_capacity=max(4096,32*proxy_vertices)`에서 다음 크기가 추가된다.

| 씬 | 두 접촉 객체의 Hessian | 정밀 기하 두 큐 |
| --- | ---: | ---: |
| 직사각형 | 127.48MiB | 5.06MiB |
| 손수건 | 65.04MiB | 2.53MiB |
| 삼각 깃발 | 49.43MiB | 1.90MiB |

이는 코드의 배열 크기 산술값이며 실제 GPU peak/예약 메모리 측정이 아니다.
후보 인덱스·gradient·BVH·proxy·trace·allocator·cuDSS 등은 별도여서 위 합계가 총 추가 메모리는 아니다.
순차 실행이므로 세 씬의 값을 동시에 합산하지 않는다.

## 가속 효과와 남은 성능 작업

직사각형 rest의 전체 VF+EE20,139,006조합 중 보수 AABB 후보는15,217개(약0.0756%)였다.
CPU broad phase 단독 비교는 전수 AABB120.746ms → LBVH2.371ms, 약50.9배였다.
이는 **후보 생성 단계의 CPU 측정**이며 전체 GPU solver가50배 빨라졌다는 뜻이 아니다.

코드상 매 힘 평가에 proxy 갱신·BVH refit/탐색·초기 교차·미분/합산이 추가되고,
Newton 이동과 실제 시간 구간에 CCD가 추가된다. 독립 검산에서도 접촉을 재평가한다.
단계별 GPU profile은 아직 없어서 어느 단계가 몇%인지 단정하지 않는다.
안전 기준을 유지하며 검토할 다음 후보는 다음과 같다. 이번에는 구현/실행하지 않았다.

- 활성 접촉0일 때 GPU 조건 분기로 미분/HVP·전체 용량 합산 작업을 줄이기.
- 검산기에서 사용하지 않는 Hessian 계산/저장을 분리하기.
- 같은 GPU·동일 상태·동일 솔버·반복 순서 교차/반복 측정으로 OFF/ON과 단계별 비용을 분리하기.

## 재현·실행 상태

비용 집계는 저장된 파일만 읽고 새 JSON 하나를 생성한다. GPU 시뮬레이션은 실행하지 않는다.

```bash
# workspace 루트; 기존 cost_report.json은 보존하므로 재실행 시 새 출력 지정
OPENBLAS_NUM_THREADS=1 .venv/bin/python \
  experiments/R1_teacher_velocity_reset/self_contact/summarize_contact_cost.py \
  --out /tmp/wind3dgs_contact_cost_repeat.json
```

중단 원본은 `experiments/artifacts/runs/p3_self_contact/three_scenes_gpu_bend500_v2`에 보존했다.
`interruption.json`과 `report.before_user_stop.json`이 사용자 종료·원본 report를 기록한다.
당시 준비한 `manual_v2`는 보존했고, 현재 수동 실행은 [실행 안내](gpu.md#세-시뮬레이션-실행)의 `manual_v3`를 사용한다.
로컬 저장 근거만 확인했고 Git fetch·다운로드·새 GPU 측정은 하지 않았다.
