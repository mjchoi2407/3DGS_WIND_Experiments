# 256배 고정 목표의 풀이 개선

2026-09-11 사용자 결정:64배 완료를 선행 조건에서 제외하고256배(Δt=1/60초)를 직접 개선한다.
수치 풀이 실패나 시간 예산 소진만으로 물리적 불가능을 판단하지 않는다. 작은 Δt는 필요한 정확도 참조이며 자동 대체 후보가 아니다.

## 완료한 검증

- n=32 원래 sub001 실패 상태(frame80,1.333333초)에서 restart240×3·고정밀 상태로1/60초 한 단계 통과.
- 선형 최대 반복720회와 모든 허용오차는 유지했다. 독립 CPU longdouble 힘·위치 갱신·에너지 장부·기하 검산 통과.
- [결과](restart_report.json): 잔차/허용한도0.983593 미만,21.864초 계산. 단기 성공이며 시간 정확도 근거는 아니다.
- 동결 n=4 CUDA0.1초/6frame [smoke](smoke_summary.json)에서256배만 실행·통과했다. `--first-candidate-only`를 생략해도 plan이 다른 후보로 전환하지 않는 것을 확인했다.
- 이전64배 궤적의3.25초 상태는 큰 변형의 별도 시험 입력으로 사용하며256배 연속 궤적의 근거로 합산하지 않는다.

후속10frame(1.35→1.516667초)을 바람 갱신과 함께 계산해 전부 독립 검산 통과했다. [결과](followup_report.json).
계산139.593초이며 일부 구간과 작은 CUDA smoke가 겹쳤으므로 속도 비교 근거로 쓰지 않는다.

## 재현과 실행

[probe_restart.py](probe_restart.py), [probe_followup.py](probe_followup.py), [probe_deformed.py](probe_deformed.py)는
`20260911_precision_segments_v4/runtime/code`를 PYTHONPATH로 사용하고 단일 BLAS/OMP thread로 실행한다.
Root의 `.venv/bin/python` 뒤에 스크립트와 새 출력 경로를 지정한다. 앞선256배 실패 입력과 후속 checkpoint는 원본으로 보존한다.
실행 원본은 `experiments/artifacts/runs/teacher_timestep_search/20260911_target256_*`이다.

현재 상태 보조 풀이를 사용하는256배 고정 장기 묶음 `20260911_target256_segments_v2`을 rest부터2.5/5/7.5/10초로 검증하도록 준비했다.
[plan](plan.json), [runtime manifest](runtime_manifest.json). 남은 본 실행 예산7998초이며64배 v4 준비본은 보존한다.
기존 wrapper는 이제256배 고정 후보를 선택한다. 수렴 진단 실행 명령(현재는 아래 시간 적분법 분기 확인을 우선하며 장기 실행 미시작):

```bash
bash experiments/R1_teacher_velocity_reset/timestep_search/run_precision_segments.sh
```

10초·시간 정확도·해상도 수렴은 미완료다. solver 개선만으로 변형/속도 정확도가 보장되지는 않는다.
바람60Hz·재료·고정 경계·원래 검산 기준을 유지한다. 방법/허용오차/비용 한도 변경이 필요하면 별도 질문한다.

## 큰 변형 상태의 추가 실패와 보완

64배 궤적의3.25초 상태에서256배 한 단계는 rest 보조 행렬·restart240×3으로 실패했다.
첫 Newton 선형 계산이720회 후 잔차6.9963e-6N, 한도6.0880e-8N으로 끝났다. [실패 분모](deformed_report.json).
이는 수렴 실패이며 물리적 불가능이나256배의 시간 정확도 실패를 입증하지 않는다.
`ColoredPreconditioner` 별도 도구는 구조적 요소 패턴을 이용해 현재 HVP를 희소 행렬로 복원하고
독립 방향의 행렬 작용을 원래 HVP와 비교한 뒤 보조 풀이를 만든다. 물리/참 잔차 검사는 유지한다.
`ShellSolvePolicy.linear_preconditioner=current` 선택 경로에 연결했다. 기본rest와 이전 동결 실행은 유지한다. [진단 스크립트](probe_current_matrix.py).

판정 원칙: 선형/비선형 수렴 실패, 반올림 오탐, 시간 초과는 풀이 개선 대상으로 취급한다.
기하 유효 범위 위반은 원인과 더 정확한 참조 결과를 확인하며, 시간 정확도 미달은 수렴 통과와 별도로 판정한다.
이 경우에도 곧바로 보편적인 물리적 불가능이라고 부르지 않고 현재 모델·정확도 요구와의 부적합 범위를 명시한다.
기준 완화나 물리 모델 변경이 필요해지는 분기에서 사용자에게 질문한다.
현재 행렬 시험 v1은 희소 LU에 longdouble 입력이 전달되어 API 형 변환 오류로 종료했다.
기존 고정밀 stepper처럼 LU 입력만float64로 변환하고 상태·원식 검산 정밀도는 유지해 v2에서 통과했다.

현재 행렬 보완 v2는 같은3.25초 상태에서256배 한 단계와 독립 검산을 통과했다. [결과](current_matrix_report.json).
Newton9회 각각의 선형 풀이가1회 반복에 통과했고, 전체33.879초·HVP2520회다. 행렬 복원/분해는 각약3.3–3.7초,
구조 패턴2478006항·276개 방향 묶음, LU 최대 약2250만항을 사용했다. 선형 반복 감소를 전체 가속률로 해석하지 않는다.
독립 물리 잔차/한도0.015891 미만, 기하 상한0.174898 미만이다. 현재 보조 행렬은 물리 모델 변경이나 시간 단계 내부 세분화가 아니다.
초기 목표 준비본 v1은 [rest plan](rest_plan.json), [rest runtime](rest_runtime_manifest.json)에 보존했다.

정식 동결 v2·current 보조 풀이로 checkpoint를 읽어 후속4frame도 통과해3.333333초에 도달했다.
[후속 결과](current_followup_report.json).191.494초 계산·각 단계 독립 CPU 원식/위치/에너지/기하 검산 통과.
큰 변형 분모에서는 첫 단계+후속4개, 총5개256배 interval이 검증됐다. 초기 실패 분모의11개 interval과 연속 궤적으로 합산하지 않는다.

[검증 집계](validation.json): 관련25개 검사 통과. n=4 CPU에서 current·256배의 중단/재개와 연속 계산을 위치1e-16m·속도1e-12m/s 기준으로 비교해 통과했다. n=32 전체 장기 재현성은 별도 검증이다.

## 국소 시간 정확도 비교

동일3.25초 상태·동일 고정 공력에서1/60초를8/16분할한 참조24개 interval 모두 독립 검산 통과.
[참조 결과](accuracy_reference_report.json), [끝 상태 비교](endpoint_comparison.json).
256배와16분할 참조의 면적에 비례하는 질량 가중 L2 상대 차이는 변위0.037591%, 속도1.636620%다.
8→16분할 참조끼리 속도 차이는0.524906%로 줄었으나, 추가32분할 결과는 아래를 따른다.
이는 하나의 주어진 상태에서의 끝 시각 비교이며 전체10초 보간/peak 기준1% 판정은 아니다.
참조의 작은 Δt는 검산 분모이고256배 목표를 대체하는 실행 후보가 아니다.
32분할 참조는 작은 dt에서 잘 수렴하는rest 보조 풀이를 사용하며 동일 허용오차·독립 원식 검산을 유지한다.

32분할 참조32개 interval도 기존 허용오차·독립 검산 통과. [결과](accuracy_refine_report.json).
[최종 국소 비교](endpoint_comparison_refined.json):256배 대32분할은 변위0.037609%, 속도1.612754%,
16→32분할 참조끼리는 변위0.000740%, 속도0.204434%다. 총56개 참조 interval을 검산했다.
참조를 세분해도256배의 속도 차이가 약1.6%로 유지되어 현재 Newmark의 국소 시간 정확도 보완이 다음 과제다.
단일 입력의 끝 시각 기준이며 수학적 오차 상한 인증·rest부터10초 전체1% 판정·물리적 불가능의 증거는 아니다.

다음 결정:256배·물리식·허용오차를 유지한 더 정확한 시간 적분법의 별도 비교 시험을 권장한다.
이 단계는 현재 Newmark 갱신식과 단계 검산 계약을 바꾸므로 사용자 분기 확인 후 진행한다.
새 적분법은 아직 구현/채택하지 않았다. 기존256배 current/Newmark 장기 준비본과 원본은 보존한다.
`code/`의 풀이/목표 옵션·검사·사용법·기록, `experiments/`의 진단/256배 wrapper·근거·기록을 변경했다.
기존 dirty worktree 보존, commit/push/fetch 없음. 외부 조회 없이 로컬 동결 원본을 사용했다.
