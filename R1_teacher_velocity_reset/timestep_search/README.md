## 직접 실행

Workspace root에서 다음 명령을 실행한다. 프로젝트 `.venv`와 기존 GPU 계산 경로를 사용한다.

```bash
bash code/scripts/run_teacher_timestep_search.sh
```

기본 결과 폴더는 `experiments/artifacts/runs/teacher_timestep_search/ten_second_v1`이다.
첫 실행에 계획·바람·소스를 동결하고, 다음 실행부터 동결된 구현과 검산된 마지막 frame을 사용한다.
준비만 하려면 `--prepare-only`, 상태 조회는 `--status-only`를 붙인다.

**이번 스크립트는 Ctrl+C로 계산까지 중단한다.** 이전 `run_remaining.sh`의 표시만 종료하는
동작과 다르다. 같은 명령으로 이어서 실행한다. 다른 터미널에서도 중단할 수 있다.

```bash
bash code/scripts/run_teacher_timestep_search.sh --stop
bash code/scripts/run_teacher_timestep_search.sh --status-only
```

2026-09-10 후속 사용자 지시에 따라 **다른 작업이 GPU를 사용 중이어도 즉시 시작한다.**
기존 실행을 자동 중단하지 않는다. 후보와 정확도 비교는 한 탐색 안에서 순차 실행한다.
Device 전체 lock은 사용하지 않으며, 같은 출력 폴더를 중복 실행하는 lock은 유지한다.
다른 GPU 작업과 자원을 공유하므로 계산 시간과 시간 제한 도달 여부에 부하 영향이 포함될 수 있다.
같은 계획이 실행 중일 때 다시 호출하면 중복 실행하지 않는다. 터미널을 유지하거나 사용자가
관리하는 `tmux` 등에서 실행한다. 자동 백그라운드 분리는 하지 않는다.

## 탐색과 판정

1. 프레임당 분할 수1→4→16→64→256, 즉 기존 대비 Δt256→64→16→4→1배로 시험한다.
   각 후보는0.5초→2초→10초의 prefix를 연장한다. 실패하면 남은 구간을 생략한다.
2. 10초 통과 후보를 찾으면 앞선 미통과 후보와의 사이에서 정수 분할 수를 기하 평균 중심으로
   좁힌다. 최대8회 정밀 탐색 후 인접 후보도 확인한다. 안정성의 단조성이나 전역 최댓값은 보장하지 않는다.
3. 가장 큰 통과 Δt와 그1/2,1/4의 세 후보를 같은10초 바람으로 끝까지 계산한다.
   후보↔1/2,1/2↔1/4,후보↔1/4의 세 비교를 모두 통과해야 추천군에 넣는다.
   실패하면 더 작은 Δt로 이동한다. 기준도 충분히 세분할 수 없거나 예산이 부족하면 추천을 보류한다.
4. 추천군에서 측정된 `compute_s`가 가장 작은 설정을 보고한다. 검산·저장·준비 및 전체 후보
   실행 비용도 별도로 기록한다. 단일 순차 탐색이므로 속도는 잠정값이며 통제된 반복 벤치마크가 아니다.

현재 구조에서는 Δt=1/(60×분할 수)다. 분할 수는1~256이고 바람 갱신 경계를 넘지 않는다.
실패한 후보를 작은 Δt로 이어 붙여 원래 큰 Δt의 성공으로 보고하지 않는다.
새 후보는 rest에서 독립적으로 시작하고, 같은 후보의 확정 frame만 재개한다.
실패한 step은 기존 solver가 입력 상태를 보존하며, 실패 prefix·시도 내역을 별도 저장한다.

| 상태 | 의미와 처리 |
|---|---|
| `stable` | 전체10초 계산·원식 검산·기하 충분조건 통과. 정확도는 별도 |
| `numerical_failure` | 유한성/반복 풀이 등 실패. 작은 Δt 후보로 이동 |
| `geometry_unresolved` | 전체 요소·시간 보간의 비뒤집힘 충분조건 미확인. 실제 뒤집힘과 구분 |
| `audit_failure` | 저장될 상태의 원식/에너지 장부 검산 실패. 탐색 중단 후 원인 검토 |
| `resource_limit` | 단계 응답 또는 후보 실행 시간 초과. 안정성 판정 보류 |
| `accuracy_unresolved` | 안정 후보는 있으나 시간 정확도 추천군을 확인하지 못함 |
| `budget_limited` | 전체 시간/후보 수 등 한도 때문에 탐색 미완료 |

매 interval에서 기존 force residual/update 허용치를 재계산하고, 고정점·에너지 장부와
Bernstein 전체 요소/시간 보간 상한을 확인한다. 에너지 증가는 외력의 일을 함께 해석하며
에너지 장부 일치가 곧 정확한 에너지 보존 또는 시간 정확도를 뜻하지 않는다.
검산은 같은 물리 구현으로 독립 재계산하는 것이며 독립 해석해나 ODE 인증이 아니다.
공간 해상도·재료 적격성의 최종 채택은 별도다. 단일10초 결과를 다른 장면의 보장으로 승계하지 않는다.

## 예산과 진행 출력

기본 한도는 **후보24개, 활성 실행 합계12시간, 후보별 누적2시간, 단계 응답300초**다.
GPU 사용 여부를 기다리는 단계는 없다. 이 값은 폭발 기준이 아닌 운영 한도다.
작은 Δt에서 후보별2시간을 넘으면 그 후보는 `resource_limit`으로 남는다.
처음부터 더 큰 예산으로 실행하려면 새 출력 폴더를 지정한다.

```bash
bash code/scripts/run_teacher_timestep_search.sh \
  --output experiments/artifacts/runs/teacher_timestep_search/ten_second_budget24h_v1 \
  --budget-hours 24 --trial-timeout 72000 --step-timeout 600 --max-trials 32
```

기존 계획은 재개 중 바꾸지 않는다. 기본 예산은 빠른 후보가 있는지 탐색하는 용도이며,
현재 가장 작은 Δt까지 모든10초 후보를 완주하도록 보장하는 예산은 아니다.
전체 상태를 보존하므로32격자/256분할/10초 한 후보의 위치·속도 배열은 압축 전 약52GB다.
큰 Δt 후보는 훨씬 작으며, 실제 디스크 사용량은 압축률과 시험 후보 수에 따라 달라진다.
원본과 실패 파일을 자동 삭제하지 않는다.

터미널에는 후보 분할 수, 실제 Δt·배율, 계산된 물리 시간/목표 시간, 단계 진행과 경과 시간을
표시한다. 프레임 진행이 없을 때도15초마다 응답을 출력한다. 상세 frame 로그는 `logs/`에 남는다.
진행률은 후보별로 표시하며 후보가 추가되는 탐색 전체의 시간 백분율을 가장하지 않는다.

## 결과·재현 파일

- `summary.md`, `summary.json`: 최대 확인 안정 Δt, 정확도 확인 최대 Δt, 계산 비용 기준 추천과 전체 후보 표.
- `plan.json`, `wind.npz`, `runtime_manifest.json`, `runtime/`: 불변 조건·실제 입력·소스 및 hash.
- `status.json`, `worker_progress.json`, `search.json`: 실행 상태, 단계 진행, 재개용 제어 상태.
- `trials/subNNN/`: 후보 config, report, 확정 frame NPZ/JSON·원식 검산, 실패 prefix/이유.
- `comparisons/`: 전체10초 Newmark 수치 보간의 변위·속도 상한과 원본 report identity.
- `recovery/`: 저장 중 중단되어 report에 아직 확정되지 않은 해당 후보 파일을 보존하는 위치.

종료 코드0은 이번 시간 세분 추천군 확인,2는 실행 완료 후 기준 미달/예산 한도,
1은 실행·검산 오류,130은 사용자 중단이다. 기존 source/바람·확정 원본이 변경되면 재개를 거부한다.

## 검증 근거

재현 가능한 구현 검사는 다음과 같다.

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 PYTHONPATH=code \
  .venv/bin/python -m unittest discover -s code/tests -p test_teacher_timestep_search.py -v
bash code/scripts/run_teacher_timestep_search.sh --smoke --device cpu \
  --output experiments/artifacts/runs/teacher_timestep_search/새로운_smoke_폴더
```

Smoke는4격자·0.1초·작은 바람으로 저장/제어를 검사하며10초 물리 조건의 증거가 아니다.
원식·기하가 통과하더라도 시간 비교가 실패하면 종료 코드2와 추천 없음이 정상이다.
초기 smoke에서 짧은 기간보다 wind knot 간격이 길어 입력 전체가0이 되는 문제를 검사가 발견했다.
Smoke 전용 knot를2 frame으로 명시하고 실제 비영 입력·움직임·비교를 확인하도록 수정했다.
본10초 설정의 knot는12 frame을 유지한다.

검증 결과와 동결 근거는 [evidence](evidence/)에 둔다. 핵심 물리 모듈이나 기존 수렴 기준은 변경하지 않았다.

GPU 대기 제거의 변경 근거는 [후속 제어 변경](evidence/no_gpu_wait/)에 별도 보존한다.
기본 `ten_second_v1`은 물리 계산0 frame·활성 계산0초 상태에서 중단되어 있었다.
실행 lock으로 중단 상태를 확인한 뒤 이전 controller/manifest를 보존하고 제어 파일만 갱신했다.
Plan·wind·물리 source는 유지하므로 기존 명령 그대로 새 제어기를 실행한다.
