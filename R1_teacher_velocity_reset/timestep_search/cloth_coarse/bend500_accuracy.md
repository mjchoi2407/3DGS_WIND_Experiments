# 1/500 Teacher 정확도 개선 진단

후속 [GPU Gauss 구현·독립 검산·동일 입력 비교](gauss_gpu_comparison.md)를 완료했다. 아래는 CPU 중심 시제품으로 수행한 선행 진단이며 후속의 참조/타이머와 혼합하지 않는다.

2026-09-14. [앞선 실패 재현](bend500_failure_diagnosis.md)의 후속으로 시간 이산화 오차를 측정했다. 기본 솔버·물성·감쇠·학습 정답·원본을 변경하지 않았다. 진단 원본은 `artifacts/runs/teacher_timestep_search/bend500_accuracy_v1`, [선별 JSON](bend500_accuracy.json)이다.

## 확인된 결론

작은 dt로 위치·속도 차이가 감소하며 기존 고차 Gauss 경로도 순간 속도 정확도 개선 가능성을 보였다. 다만 전체 학습데이터의 시간 수렴/공간 수렴/독립 GS 매핑 또는 접촉 적격성을 통과한 것은 아니다. 이번 확정 범위는 같은2초 checkpoint 이후의 국소 구간이다.

## 한 프레임의 Newmark 세분화

동일 source raw hi/lo 상태에서2.00~2.0166667초를 계산했다. 모든 Newmark 후보는 FP64 hi/lo·같은 물성·외력·힘/위치/검산 허용오차를 유지한다. Frame-start 힘은 해당 구간에서 고정한다. 추가 dt1/61440 및1/122880의 각1024/2048단계 모두 solver/독립 audit flag0·factor/time 검사 통과다.

오차는 coarse와 fine의 동일 시각 노드장을 consistent mass M으로 적분한 공간 RMS에 시간 사다리꼴 적분을 적용한다. 상대 속도 분모는 fine의 질량·시간 RMS 속도다. 특정 노드 성분 최대치와 다르며 row-sum 질량을 양의 lumped 질량으로 해석하지 않는다.

| dt 비교 | 위치 질량·시간 RMS 차이 | 속도 상대 RMS 차이 | 프레임 평균 속도 상대 차이 |
| --- | ---: | ---: | ---: |
| 1/7680 ↔ 1/15360 | 0.03488mm | 43.50% | 0.665% |
| 1/15360 ↔ 1/30720 | 0.01839mm | 35.76% | 0.332% |
| 1/30720 ↔ 1/61440 | 0.00984mm | 28.59% | 0.169% |
| 1/61440 ↔ 1/122880 | 0.00488mm | 20.18% | 0.0886% |

평균 속도는 프레임 순이동/시간의 별도 진단이며 순간 속도 label을 대체하지 않았다. 전체 속도 RMS 크기는 약0.5495m/s로 비슷하나 실제 벡터 차이는 크다. 큰 움직임/에너지가 비슷해도 순간 속도가 시간 수렴했다는 뜻은 아니다.

차이가 큰 노드는 비교마다 달라진다(예: rest xyz=(.5625,0,-.125),(.5,0,-.125),(1,0,.5),(1,0,-.5)m). 한 노드의 outlier만으로 설명되지 않는다. Rest stiffness/consistent mass의 큰 고유값4개에서15.55~15.92kHz의 선형 진동수가 나왔다. 변형 상태의 고유값이나 해당 모드의 실제 기여율 측정은 아니며, 빠른 진동의 위상 오차라는 해석을 보조하는 근거다.

추가 Newmark1프레임 풀이·진단 시간은 dt1/61440에서49.12초,1/122880에서141.14초였다. 매substep 동기화/진단을 포함하며 setup·저장·독립 검산은 제외한다. CPU 분석이 일부 GPU 실행과 겹쳤고 부하/클록 통계적 통제는 없으므로 엄밀한 성능비가 아니다. 시간 세분화의 비용이 크다는 관측으로만 사용한다.

## 더 짧은 구간의 고차 적분 대조

기존 `p3_shell_gauss.gauss_step`의 coupled 보조 풀이를 사용했다. 새 GPU 상주 Gauss를 구현한 것은 아니다. 이 시험의 범위는 **2.0초부터 원래1substep 폭1/3840초**로, 위1프레임 표와 혼합하지 않는다. Newmark는 raw f64 hi/lo, Gauss는 기존 CPU longdouble 상태/GPU hi/lo 힘 평가를 사용한다. 같은 원시 위치/속도에서 시작하며 Gauss 입력에서는 기존 경로대로 longdouble 합성한다.

Newmark256분할(dt1/983040초) 끝 상태를 비교 기준으로 두었다. 이 기준 자체의 검사는128↔256분할이며, 양쪽 독립 검산 통과 및 끝 속도 상대 질량 RMS 차이0.1056%다. 이는 exact solution 보증이 아니다.

| 짧은 구간 방법 | 끝 속도 상대 질량 RMS 차이(256분할 대비) | 위치 성분 최대 차이 | 풀이·진단(s) |
| --- | ---: | ---: | ---: |
| Newmark128분할 | 0.1056% | 0.0461µm | 8.05 |
| Newmark256분할 | 기준 | 기준 | 13.69 |
| Newmark32분할 | 2.0733% | 0.941µm | 이 짧은 구간 별도 시간표 없음 |
| 4차 Gauss1분할 | 21.2378% | 17.621µm | 3.30 |
| 4차 Gauss4분할 | 6.9069% | 4.588µm | 9.89 |
| 4차 Gauss8분할 | 2.4585% | 1.165µm | 14.34 |
| **6차 Gauss8분할** | **0.1499%** | **0.0723µm** | **16.89** |

초기4차Gauss8 vs Newmark32의0.82% 차이를 정답 오차로 사용하지 않는다. 더 정밀한256기준에서는2.46%였다. 기준 자체의 오차를 확인해야 한다는 사례다.

6차Gauss8은 짧은 끝 상태의 정확도 후보이나 **독립 Gauss 검산은 미연결**이다. 반환된 stage residual/update 검사와 힘 방정식 수렴은 확인했지만 기존 Newmark 전용 audit를 적용해 통과했다고 기록하지 않는다. CPU 보조 행렬 구축/분해 비용으로 현재는 Newmark128보다 느리다. Gauss 최종 work/energy ledger 값은 적분법 고유의 수치 에너지 변화이며 기존 audit error와 같은 열로 비교하지 않는다.

## 다음 권장 작업과 미완료 범위

1. 정확도 기준을 완화하거나 속도를 평균/감쇠시키지 않는다. FP64 hi/lo 기본을 유지한다.
2. 고차 적분은 가능성을 보인 후보로 둔다. 기존 시제품의 반복별 보조 행렬 구축 비용을 줄이고 stage·힘·업데이트·에너지·구간 기하의 독립 검산을 연결해야 실제 성능/정확도 대조가 가능하다.
3. 그 뒤 동일 초기 rest부터 전체 궤적의 시간 수렴을 확인한다. 이번은 이미 coarse dt로 계산한2초 상태를 공통 seed로 사용했으므로0~2초의 누적 오차를 검증하지 않았다.
4. 학습에 쓸 위치·순간 속도·work·normal 등 실제 label의 공간/시간 오차와 mapping 오차를 분리한다. 이번 최대 성분/RMS 진단만으로 R1 canonical threshold를 새로 정의하거나 완료 처리하지 않는다.
5. 추가 감쇠·물성 변경·시간 평균 label·접촉은 별도 물리/연구 선택이며 이번에는 적용하지 않았다.

## 재현과 검증

`code/scripts/analyze_bend500_accuracy.py`는 질량 적분 상수장 검사와 동일 초기 상태를 확인한다.
`diagnose_gravity_bend500.py --split 16/32`는1프레임, `probe_bend500_short_reference.py --split 128/256`은 원래1substep 구간이다.
`probe_bend500_gauss_accuracy.py --stages 2/3 --subdivisions 1/4/8 --out <새경로>`는 같은 짧은 구간의 기존 Gauss 후보다.
모두 source의 frozen runtime을 PYTHONPATH로 사용했고 각 출력을 별도로 보존했다. 입력/source hash는 앞선 진단/원본 manifest를 계승하며 이번 driver 사본·추가 결과는 새 manifest로 보존한다.
Gauss의 기존 analytic oscillator 4차/6차 수렴·에너지/control 테스트2개도 통과했다. 실제 천의 독립 검산을 대신하지 않는다. 서브컴 경로에서 해당 중력 run의 추가 근거는 찾지 못했고 외부 fetch/다운로드는 하지 않았다. 원본 재개·기본 코드 변경·commit·push 없음.
