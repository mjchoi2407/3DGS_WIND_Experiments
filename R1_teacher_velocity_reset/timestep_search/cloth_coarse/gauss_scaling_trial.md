# Gauss 행·열 스케일링과 FP64 잔차 보정 비교

확인 기준: 2026-09-15. [선행 FP32 비교](gauss_fp32_trial.md)의 동일 직사각형1/500 입력으로 별도 시험을 완료했다. **보조 행렬 스케일링 단독으로는 정체가 해결되지 않았다. FP64 참 잔차와 FP32 선형 보정을 결합한 후보는 두 국소 프레임의 원래 검산을 통과했고, 바람 프레임 풀이 시간이 약11% 감소했다.** 기본 경로 채택과 장기 teacher 검증은 미완료다. 기존 원본/기본 솔버/dt/물성/학습 Gate를 변경하지 않았다.

## 비교 구성과 분모

출력은 `artifacts/runs/teacher_timestep_search/gauss_scaling_trial_v1`이다. 원본 입력은 선행 FP32 run의 preload frame0, wind frame120(바람2초)이며 SHA-256이 일치하는 runtime과 입력을 복제했다. 소스와 라이브러리·입력은 `manifest.json`, 보정 버전별 소스는 `mixed*_manifest.json`, 명령/반환은 `commands.json`, `mixed_commands.json`, `audit_commands.json`에 보존한다. main GTX1080Ti에서 모든 GPU 측정은 순차 수행했다. 서브컴 결과의 장치/씬/구간을 이 표에 혼합하지 않는다.

1. FP32 단독 기준 ↔ FP32 행·열 평형화: 종료 기준은 동일하다. preload medium과 wind loose는 각각512단계/한 프레임(1/60초), wind medium은128단계(1/240초) 국소 정체 검사다. 서로 다른 구간의 시간이나 완주 여부를 혼합하지 않는다.
2. FP64 strict ↔ FP64 보정+FP32 선형 풀이: 같은 strict 정책과512단계/한 프레임을 비교한다. 모든 경우 dt=1/30720초다. 실제 바람8단계 smoke는 본 프레임 비교와 별도다.

medium/loose 정책은 선행 보고서와 동일하다. 이번 스케일링은 cuDSS 보조 행렬에 명시적으로 적용하며, 전체 물리식의 단위/외력을 바꾸거나 원래 GMRES 잔차 norm을 완화하지 않는다. 초기 중력을 무시했던 loose preload는 다시 유효한 가속 후보로 포함하지 않았다.

## 보정 경로와 검증 계약

`R P C`와 RHS/해의 일관된 배율 변환을 먼저 단독 비교한다. `mixed_v3`는 이 스케일링 위에 FP64 상태/힘/가속도/에너지/참 선형 잔차, FP32 HVP/GMRES/보조 행렬 조립/분해/풀이를 결합한다. FP32 내부 GMRES 목표는1e-5이나 FP64 참 선형 잔차는 원래 정책의 기준을 만족해야 한다. 보정4회 한도/정체는 실패로 판정한다.

작은 fixture의 초기 보정 후보는 수렴 후반의 매우 작은 RHS에서 정체했다. 후속 후보는 RHS norm으로 정한 2의 거듭제곱 정규화와 보정량 역변환을 추가해 동일 기준을 통과했다. 이 후속은 행렬 스케일링 단독과 구분하며, 실패한 버전의 로그/소스도 보존한다. 최초 혼합 package의 CPU 모델 타입 불일치는 별도 import 연결로 바로잡았으며 물리 모델을 교체하지 않았다.

독립 검산은 별도 FP64 runtime이 저장된 모든 stage에서 힘·갱신식·에너지 장부·기하·고정점·유한성을 재구성한다. FP32/혼합 풀이가 사용한 캐시를 승인 근거로 재사용하지 않는다. 검산 초과를 기록하며 학습 적격성은 자동 승계하지 않는다. 행렬 probe1e-5와 물리적 독립 검산 기준은 별개다.

## 시간 범위

초기8단계 warmup 후 같은 상태를 복원해2회 측정하며 끝 GPU 완료를 포함한다. 별도 상태/stage 기록 replay는 풀이 타이머에서 제외한다. 행렬 스케일링과 FP64 보정의 추가 비용은 풀이 타이머 안에 있다. 생성기 전체 초기화/외력 갱신/파일 저장 시간은 포함하지 않는다.

독립 검산은 준비·업로드를 제외하고 warmup1회 후1회 측정한다. 풀이+검산은 각각 측정한 구간의 합이다. 이전 run의 타이머 편차가 컸으므로 이번에 다시 측정한 기준을 사용하며 이전 시간과 배속을 직접 계산하지 않는다. 두 반복만의 중앙값이므로 작은 시간 차이는 유의한 가속으로 해석하지 않는다.

## 채택 판단

스케일링 단독은 채택 근거가 없다. 혼합 후보는 추가 비용을 포함해 바람에서 소폭 이득과 원래 기준의 정확도를 동시에 보였으므로 후속 후보로 보존한다. 초기 처짐의2% 차이는 반복 편차와 비슷해 가속 확정 근거가 부족하다. 큰 시간 감소가 필요하다는 요구를 이번 후보만으로 해결했다고 보지 않는다.

이번 범위는 직사각형의 저장된 두 상태에서 각각1/60초다. 다른 메시/장시간/시간·공간 수렴/접촉/학습 성능을 검증하지 않았고 기본 솔버를 교체하지 않았다. 따라서 teacher 데이터 채택과 R1 canonical 완료/Gate는 계속 보류한다.

## 재현

준비/실행은 `code/scripts/prepare_gauss_scaling_trial.py`, `prepare_gauss_mixed_trial.py`, `run_gauss_scaling_trial.py`와 각 artifact의 동결 driver를 따른다. 스케일링 검증은 `check_gauss_equilibration.py`, 혼합 경로의 FP64 대조/CPU longdouble 검산/host 조회 금지/재시작/실패 보존 검증은 `check_gauss_mixed.py`다. 동일 root 재생성이나 기존 결과 덮어쓰기는 하지 않는다.
