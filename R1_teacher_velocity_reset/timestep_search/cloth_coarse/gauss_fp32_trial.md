# Gauss FP32 hi/lo 개발 비교

확인 기준: 2026-09-15. 기본 솔버와 동결된 세 씬은 변경하지 않는다. 본 문서는 별도 정밀도 후보의 개발 진단을 소유한다. 학습 적격성 및 장기 안정성은 미검증이다.

## 입력과 비교 조건

원본은 `artifacts/runs/teacher_timestep_search/gauss6_split8_bend500_reference_rectangle_v1`이다. 완료된 직사각형1/500 실행에서 preload frame0, wind frame120의 raw FP64 hi/lo 상태와 해당 프레임 외력을 추출했다. 원본 chunk의 선언 SHA-256과 일치함을 확인했다. 서브컴의 삼각형/손수건은 이번 정밀도 수치 비교에 섞지 않았다.

출력: `artifacts/runs/teacher_timestep_search/gauss_fp32_trial_v1`. `manifest.json`은 초기 runtime·입력·native library를, 각 입력의 `provenance.json`은 원본을 식별한다. `config.json`은 각 lane의 정책, `report.json`은 풀이 완료/실패 및 카운터, `fp64_audit.json/.npz`는 원래 기준 검산, `analysis.json`은 상태 차이를 보존한다.

같은 GTX1080Ti에서 순차 실행한다. 각 구간은1/60초 실제 한 프레임, dt=1/30720초,512단계다. Gauss3stage6차·물성·고정점·외력은 동일하다. FP32 입력은 원래 두 FP64의 합을 FP32 hi/lo로 재분할하며, 외력은 FP32 저장 시 반올림된다. CPU 구조 준비와 작은 Gauss 변환은 FP64다.

## 후보와 기준

| 정책 | 힘 절대 N / 상대 | 변위 절대 m / 상대 | 선형 상대 |
|---|---|---|---|
| strict | 원본 plan의 공식 기준 | 원본 plan의 공식 기준 | 원본 plan의 공식 기준 |
| medium | 1e-6 / 1e-5 | 1e-10 / 1e-6 | 1e-5 |
| loose | 1e-4 / 1e-3 | 1e-8 / 1e-4 | 1e-3 |

이는 단순히 조금 완화한 기준이 아니라 원래 기준과 여러 자릿수 차이가 나는 개발 정책이다. FP32의 힘/HVP·GMRES·희소 분해/풀이·stage와 상태 갱신을 전환하고 기존 안정화 변형률/법선 쌍 보정을 적용했다. 내부 행렬/HVP probe 상대 기준도 FP64의1e-10에서 FP32의1e-5로 구분했다.

검산은 원래 FP64 물리식·기준을 유지한다. 유한한 검산 초과는 기록하며 후보를 학습 통과로 처리하지 않는다. 반복 풀이 자체가 실패하면 미완성으로 판정한다. 실패까지 걸린 시간은 완성 프레임 시간이나 가속률로 사용하지 않는다.

## 시간과 오차 분모

8단계 warmup 후 같은 초기 상태를 복원하여 전체 프레임2회를 측정한다. 마지막 GPU 완료를 포함하며 초기 준비/컴파일은 제외한다. 별도 replay는 매 단계 상태와 stage를 저장하므로 측정에 포함하지 않는다. FP64 독립 검산은 준비/업로드를 제외한4회 중 첫 회를 버린3회의 중앙값이다. 풀이+검산 합은 두 측정의 합이며 실제 통합 생성기의 총시간이 아니다. 반복 간 시간 편차가 커 단일 배속으로 일반화하지 않는다.

끝 상태 상대 차이는 consistent mass norm, 시간 전체 차이는 동일512단계 표본의 mass–time norm이다. 위치 최대 차이와 속도 최대 차이는 노드별 Euclidean norm이다. FP64 strict를 비교 기준으로 사용하되 exact solution이나 시간 수렴 참조로 부르지 않는다. 정밀도 변경과 dt 변경을 혼합하지 않았다.

## 재현 도구

workspace root에서 `PYTHONPATH=code .venv/bin/python code/scripts/prepare_gauss_fp32_trial.py --out <새 출력>`으로 입력과 runtime을 동결한다. `run_gauss_fp32_trial.py`는 선택한 runtime을 `PYTHONPATH`로 지정하고 해당 native cuDSS/shim을 연결한 별도 프로세스로 실행한다. 구체적인 실행은 artifact의 `commands.json`, `run_trial.py`, `audit_trial.py`를 따른다. 서로 다른 lane은 같은 GPU에서 동시 측정하지 않는다.

`PYTHONPATH=code .venv/bin/python code/scripts/analyze_gauss_fp32_trial.py <출력>`으로 저장 결과를 분석한다. 원본과 기존 run의 덮어쓰기는 허용하지 않는다.

## 현재 판정과 해석

- FP32 medium은 초기 중력 프레임의 위치/속도 차이가 작지만 원래 힘 잔차 기준을 일부 초과한다. 바람 구간에서는 Newton 반복 한도(failure1)에 걸려 두 측정 모두 미완성이다. 실패 전 완료 단계는 각각92/512,26/512다. 이 시간의 중앙값을 가속률 계산에 사용하지 않는다.
- FP32 loose는 초기 중력에서 Newton/GMRES가0회이며 위치/속도가0에 머문다. 외력이 절대 허용오차 아래로 묻힌 결과로, 유효한 가속 후보에서 제외한다. 바람 구간은 완주하나 원래 힘·갱신·에너지 장부 기준을 모두 초과한다.
- 같은 허용오차의 FP64 대조는 dtype 변경의 효과를 분리한다. FP64 strict와 FP32 완화 후보의 차이에는 반복 감소도 포함된다. 느슨한 FP64 역시 공식 검산 통과를 자동 보장하지 않는다.
- 끝 상태는 마지막 timed repeat, 전 구간 상태와 독립 검산은 별도 replay다. FP32 바람 loose의 replay와 timed 끝 상태 최대 성분 차이는 위치4.36e-8m, 속도7.95e-4m/s였다. 동일 입력의 bitwise 재현을 주장하지 않으며 FP32 medium의 실패 시점도 반복마다 다르다.
- 새 FP64 strict 끝 상태와 원래 연속 실행의 해당 프레임 끝 상태를 대조했다. 최대 성분 차이는 preload 위치1.85e-17m/속도1.41e-12m/s, wind 위치6.40e-17m/속도7.92e-13m/s다. 상세 값은 `original_endpoint_comparison.json`에 있다.
- 이번 표본만으로 전 구간 FP32, 장기 안정성이나 teacher 적격성을 채택하지 않는다. 다음 후보는 FP32 반복 풀이를 활용하면서 FP64의 참 잔차·상태 보정·에너지 재평가 비용까지 포함해 비교하는 방식이다. 아직 그 혼합 Gauss 경로의 효과를 입증한 것은 아니다.

## 확정된 표본 결과

총8개 lane 중7개 한 프레임 완료,1개(FP32 medium 바람)는 두 측정 모두 실패했다. 완료된7개 replay의3584단계를 원래 FP64 식으로 검산했다. 아래 시간은 초, 상대 속도 차이는 FP64 strict 대비 끝 상태의 질량 norm 백분율이다.

| 구간·경로 | 풀이 중앙값 | FP64 검산 중앙값 | 합산 | 속도 차이 % | 원래 검산 flag: 단계 수 |
|---|---:|---:|---:|---:|---|
| preload_fp32_loose | 2.265 | 22.160 | 24.425 | 100 | 1: 512 |
| preload_fp32_medium | 32.891 | 22.337 | 55.228 | 0.000129743 | 0: 97, 1: 415 |
| preload_fp64_medium | 56.897 | 21.644 | 78.542 | 8.20403e-07 | 0: 512 |
| preload_fp64_strict | 116.322 | 21.982 | 138.304 | 0 | 0: 512 |
| wind_fp32_loose | 31.768 | 21.092 | 52.860 | 0.106506 | 7: 512 |
| wind_fp32_medium | 미완성 | — | — | — | Newton 한도 실패 |
| wind_fp64_loose | 62.636 | 21.584 | 84.220 | 0.102724 | 1: 512 |
| wind_fp64_strict | 141.846 | 10.440 | 152.286 | 0 | 0: 512 |

flag0은 기준 통과,1은 힘,2는 갱신식,4는 에너지 장부 초과이며7은1|2|4다. 완료 표본에서 비유한/고정점/기하 flag는 없었다. 원래 FP64 strict는 두 구간 모두 통과했다.

- 같은 medium 기준의 preload: 풀이 1.73배, 검산 합산 1.42배. GMRES 총횟수 FP64 738 / FP32 738.
- 같은 loose 기준의 wind: 풀이 1.97배, 검산 합산 1.59배. GMRES 총횟수 FP64 1014 / FP32 1015.

같은 loose 기준의 바람 끝 속도에서 FP32↔FP64 차이는0.017962%다. FP32 loose↔strict FP64의0.106506% 차이와 분모가 다르다. FP32 loose의 바람 전체 프레임 속도 mass–time 차이는0.069054%이고, 최대 노드 속도 차이는0.025373m/s였다. 끝 위치 최대 차이는2.752518e-6m, 전 구간 최대는7.442114e-6m였다.

바람의 최대 변형률 상한은 strict FP64 0.16084219, loose FP32 0.16084302이며 최대 곡률 상한은42.33814와42.33825다. 이는 실제 최대 늘어남의 정확한 값이 아닌 구간 인증 상한이다. FP32의 최대 갱신 결함은 위치1.087e-11m/속도5.112e-8m/s, 에너지 장부 재평가 차이는1.481e-8J였다. 에너지 수치 잔여 자체와 장부 재현 차이를 구분하며 전체 장기 드리프트는 미측정이다.

FP64 medium preload는 원래 검산도512단계 모두 통과했다. 허용오차 확대가 모든 구간에서 동일한 오차를 만든다고 가정할 수 없으며, 이 한 프레임 결과만으로 기본 정책을 완화하지 않는다. 외부 웹 조회/fetch 없이 로컬 코드와 동결 결과를 사용했다.

검증: 초기 동결 manifest373개 파일의 SHA-256 일치 확인, 최종547개 근거 파일의 `evidence_manifest.json` 생성, 새4개 스크립트의 Python 구문 검사와 관련 저장소 diff 공백 검사를 통과했다. 기록 replay 차이는 위 제한을 따른다.

후속 구현·비교는 [행·열 스케일링과 FP64 잔차 보정](gauss_scaling_trial.md)을 따른다. 위 수치는 당시 FP32 단독 후보의 결과로 보존한다.
