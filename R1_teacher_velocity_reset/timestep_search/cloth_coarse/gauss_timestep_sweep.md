# 타임스텝과 반복 수렴 비용 비교

2026-09-14. **Newmark는 dt를 절반으로 줄이면 단계 수가 두 배가 되어도 총 풀이가 빨라졌다.** 두 국소 상태에서 풀이+GPU 검산 합산은 기존 설정 대비7.83배/9.06배 짧았다. 그러나 이 설정의 끝 속도 참조 차이는24.36%/25.04%이므로 teacher 정확도를 확보한 가속안으로 채택하지 않는다.

[선행 GPU 비교](gauss_gpu_comparison.md)의 후속이다. [선별 JSON](gauss_timestep_sweep.json), [비용·정확도 그림](../../../artifacts/runs/teacher_timestep_search/gauss_gpu_timestep_sweep_v1/timestep_cost_accuracy.png). 원본은 `artifacts/runs/teacher_timestep_search/gauss_gpu_timestep_sweep_v1/`다.

## 비교 조건

- 1/500 깃발의 동일한 두 raw FP64 hi/lo 시작 상태: 바람2.0초 및 실패 시도 직전2.0145833333초. 각 후보는 **같은1/3840초 구간**을 끝까지 계산한다. 원래 dt를1·2·4·8·16·32분할한 Newmark/GPU Gauss6차의24개 새 lane이다.
- 메시384삼각형·1813 P3 계산점, 물성·고정점·원본 frame-start 외력 배열·공식 검산 허용오차를 유지했다. Gauss는3단계6차다. 접촉·감쇠·정밀도·솔버 기본값을 변경하지 않았다.
- 모든 후보는 같은 상태에서 보조 행렬을 새로 준비한다. 재사용 간격64는 기존 의미인 Newton 선형 풀이 횟수 기준이다. 이번24개 lane은 각각 실제 행렬 구축1회다. 과거 실패의 연속 cache 상태는 재현하지 않는다.
- main GTX1080Ti에서 후보를 순차 실행했다. 각 구간 warmup1회 후3회 중앙값, GPU 완료 동기화 포함. 별도 replay에서 원시 상태·stage·에너지와 검산을 저장했다. 외부 compute process는 시작 전 조회에서 없었지만 그래픽 부하/클록/장치 독점은 통제하지 않았다.
- GPU 검산도 동일한 장치에서 준비/warmup을 제외하고3회 중앙값이다. **합산은 별도 측정한 풀이+GPU 검산의 합**이며 모델·solver 초기화, 입력/출력, 기록 replay와 완성된 데이터 생성기의 end-to-end 시간은 아니다.
- 비교 참조는 선행 run의 각 seed별 Newmark512 끝 상태를 해시 검증 후 복사했다. 이전 참조의 시간은 이번 표에 포함하지 않는다. 새로운 후보 속도는 모두 이번 실행에서 측정했다.
- 서브컴 `artifacts/runs/sub_pc/`의 config/report/manifest에서 이번 GPU Gauss 비교에 해당하는 추가 실행을 찾지 못했다. 이번 표는 main의 동일 입력·장치 비교다. 외부 fetch/다운로드 없음. 원본 입력/참조10개와 cuDSS/shim의 해시는 environment.json에 보존했다.

## 반복 수렴과 시간 적분 정확도를 분리한 해석

Newmark1→2분할에서 총 GMRES는650→26회,740→25회였다. 풀이만의 개선은8.30배/9.57배다. 4분할부터는 이번 탐색에서 다시 느려졌다. 단계당 반복 수가 줄더라도 총 단계 수와 검산 비용을 더해야 한다. 보조 행렬 구축 횟수는 모두1회이므로 구축 횟수 감소로 설명되는 결과는 아니다.

작은 dt에서는 관성 항의 비중이 커지고 한 단계의 변화가 작아져 선형계와 보조 풀이가 다루기 쉬워질 수 있다. 이는 이번 반복 수 감소와 일관된 설명이다. 조건수나 각 Newton 잔차 이력을 별도로 측정해 원인을 분해한 것은 아니다.

Gauss는 이번1→32분할에서 **전체 비용이 계속 증가**했다. 단계당 GMRES는 대체로 줄었지만 총 GMRES와 단계 수 증가를 상쇄하지 못했다. 따라서 작은 dt가 항상 빠르다는 정책이나 모든 적분기에 동일한 최적 dt를 적용할 근거는 없다.

끝 속도 차이는 정밀 참조 대비 질량 가중 상대 L2이며, 공식 운동방정식 잔차와 다른 지표다. Newmark2는 반복 풀이 검산을 통과해도 끝 속도 차이가24–25%다. Gauss1도15% 이상이다. 가장 빠른 설정이라는 이유만으로 학습 label에 사용하지 않는다. Gauss8은0.172–0.176%, Gauss16은0.00591–0.00623%로 선행 정확도 결과를 재현했다.

Gauss32의 참조 차이는0.00878–0.00915%로 Gauss16보다 약간 커진다. 이를 정확도 악화로 단정하지 않는다. 기존 Newmark256↔512 차이도0.02648–0.02758% 남아 있어 참조가 정확해가 아니기 때문이다. **Gauss16↔32 자체의 차이는0.00361–0.00370%**(위치 성분 최대1.76–1.99nm)이며, Gauss8↔16보다 훨씬 작다. 시간 세분화 차이를 직접 확인하되 참해 오차 인증이나 전체 궤적 수렴으로 승격하지 않는다.

이번 탐색에서는 속도만의 최소가 Newmark2분할이고, 정확도까지 고려한 후속 검증 후보는 Gauss16을 유지한다. 이를 teacher 허용오차나 자동 dt 선택의 새 기준으로 채택하지 않는다. 현재 seed 이전의 누적 오차, 한 프레임 이상 연속 cache 사용, rest 시작 장기 궤적과 전체 생성 시간은 별도 검증 대상이다.

## 검산·재현과 기록

- 24/24개 계산의 기존 후처리 검산 통과. Newmark126개, Gauss126개 고유 substep(378개 내부 stage)다. 시간 측정 반복과 기록 replay를 서로 다른 궤적으로 중복 집계하지 않는다.
- 별도 GPU 검산도24/24개 통과했다. Gauss는 CPU longdouble 검산과 GPU의 힘/갱신/에너지 장부/P3×cubic 기하 판정을 대조하고 손상 가속도 거부도 확인했다. 원래 유한성·고정점·허용오차를 유지했다.
- 모든 lane의 측정3회에서 완료 단계·GMRES·구축·failure 카운터가 같고 source 변경이 없었다. 끝 상태와 검산 replay의 기존 수치 재현성 기준도 통과했다.
- 기존 비교 manifest224개 파일이 변경 없이 일치하고, 새 run manifest373개 파일의 해시도 검증했다. 집계/그림 스크립트 문법 검사와 결과·카운터·합산·문서 링크 대조를 통과했으며 그림을 직접 확인했다. R1 PDF34쪽 빌드 및 전달 bundle의 R1두 항목 갱신/나머지 byte 보존을 확인했다.
- GPU 검산의 현행 태그는 `gpu_audit_v3`다. 초기 검산 준비는 동결 cuDSS 환경변수 누락으로 패키지 탐색에서 실패했으며 최초 log와 부분 `gpu_audit_v2`를 보존했다. 라이브러리를 명시해 별도 태그로 재실행했다. 물리/솔버 실패 분모에 포함하지 않는다.
- 실행은 원본의 `run_sweep.py`, 검산/집계는 `postprocess_v3.py`에 정확한 인수를 보존한다. workspace 루트에서 실행한다. `CUDSS_LIBRARY_PATH`와 `LD_PRELOAD`는 선행 보고서의 동결 library/shim을 재사용한다. 이 스크립트는 새 run용이며 기존 디렉터리를 덮어써 재실행하지 않는다.
- 집계 API: `code/scripts/analyze_gauss_gpu_comparison.py <root> --reference reference_import --audit-tag gpu_audit_v3`. 인접2배 시간 분할의 차이도 출력 JSON에 기록한다. 그림: `code/scripts/plot_gauss_timestep_sweep.py <root>`.
- 구현 기본값/물리 계약/teacher 판정은 유지한다. R1에는 국소 타임스텝 비용 대조의 범위와 보고서 링크만 반영한다. R0/master/sketch의 완료/claim 변경은 없다. stage/commit/push 없음.
