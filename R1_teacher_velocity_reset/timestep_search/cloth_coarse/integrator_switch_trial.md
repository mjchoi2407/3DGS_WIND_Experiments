# Newmark64 우선·Gauss6차 재계산 비교

확인 기준: 2026-09-15. 사용자 요청의 Newmark64 우선/Gauss 재계산 경로를 구현하고 두 저장 상태에서 반복 비교를 완료했다. **원상 복원/전환과 검산은 정상 동작했지만 실제 네 번의 전환 시험 모두 Gauss를 선택해 가속 효과를 얻지 못했다.** 두 방법 모두 FP64 hi/lo이며 FP32 실험과 혼합하지 않는다. 기본 생성기를 교체하거나 학습 Gate를 변경하지 않았다.

## 입력과 비교 조건

- 원본: `artifacts/runs/teacher_timestep_search/gauss_scaling_trial_v1/inputs/{preload,wind}`. 동일 직사각형1/500의 초기 처짐 frame0, 바람 frame120에서 각각 한 프레임1/60초를 계산한다.
- 비교 root: `artifacts/runs/teacher_timestep_search/newmark_gauss_switch_v1`. `runtime/`은 선행 FP64 소스/라이브러리를 복제하고 전환 module만 추가했다. 초기192파일 manifest와 원본 입력 hash를 보존한다.
- Newmark64: dt=1/3840초. 오차 감시용 Newmark128: dt=1/7680초. Gauss6차: dt=1/30720초, 프레임당512단계. 기존64 substep 각각의8분할이라는 뜻이다.
- 각 프레임 내 held 공력/중력, 재료, 고정점, 원래 힘/선형/갱신식 검산 기준은 동일하다. 각 후보는 동일 원시 hi/lo 시작 상태를 사용한다.
- 메시384삼각형,1813 P3 계산점이다. 다른 해상도나 다른 메시 결과로 확대하지 않는다.
- main GTX1080Ti에서 순차 계산한다. `artifacts/runs/sub_pc/`도 조회했으며 이번 새 전환 runtime에 해당하는 별도 계산을 표에 혼합하지 않는다. 원격 fetch/download는 하지 않았다.

## 선택 방식과 정확도 경계

Newmark64의 풀이 또는 독립 검산이 실패하면 바로 Gauss로 재시도한다. 통과하면 같은 원본에서 Newmark128도 풀이/검산한다. 공통65시각의 consistent mass 가중 RMS 차이를 GPU에서 계산하고 위치/속도를 모두 확인한다. 임계값은 상대1e-3에 위치 절대1e-10m, 속도 절대1e-8m/s를 더한 **개발용 전환 지표**다. 매 시각의 `차이/(절대 지표+상대 지표×세분 결과 RMS)`가1 이하일 때만64분할 결과를 채택한다.

이는 공식 teacher 허용오차나 정확한 시간 오차 상한이 아니다. 점근 수렴을 가정해 차이를3으로 나누지 않으며, 두 Newmark 결과가 같은 오류를 공유하는 가능성은 Gauss 참조로 별도 확인한다. Gauss 비교 또한 같은 dt의 참조일 뿐 연속시간 정답을 인증하지 않는다. 임계값 민감도는 저장된 지표의 사후 분석으로 구분하며 허용오차를 바꾼 장기 실행으로 간주하지 않는다.

기하 검사는 기존 `local_metric` 충분조건을 유지한다. 큰 회전에서 실패했던 투영 조건을 전환 trigger로 부활시키지 않으며, 실제 자기충돌 검사/응답은 미구현이다. Newmark 결과에 오차가 있으면 그 상태를 Gauss로 이어가지 않고 원본 checkpoint로 돌아간다. 모든 후보가 실패하면 확정 상태는 보존한다.

## 타이머와 재현

`run_integrator_switch_trial.py`는 같은 프로세스에서 첫 반복 adaptive→Gauss, 두 번째 Gauss→adaptive 순서로 실행한다. 초기 모델/graph/factor 준비와 입력 업로드, 출력 파일 저장은 측정에서 제외한다. 측정에는 GPU 원상 복원·모든 후보 계산·GPU 상태/stage 기록·수행한 독립 검산·오차 지표·프레임 경계 CPU 조회·최종 채택을 포함한다. 개별 Newton/GMRES/적분 단계의 CPU 수치 조회는 없다.

Gauss는 각 단계 직후 검산하므로 해당 시도의 `solve_record_s`에 검산을 포함한다. Newmark 검산은 프레임 계산 후 실행하여 `audit_post_s`로 분리한다. **방법 간 총비용 비교에는 `total_s`를 사용한다.** 선행 별도 풀이/검산 시간의 합과 직접 배속을 계산하지 않는다. 파일 저장·외력 갱신까지 포함한 전체 데이터 생성기 실측도 아니다.

원본 명령/반환은 `commands.json`, 실행별 config/report와 모든 시도 trace/stage/검산은 `{preload,wind}/` 아래 보존한다. 동결된 driver와 runtime을 사용하며 기존 출력 경로에 덮어쓰지 않는다. 소유 API와 캐시/graph 계약은 [구현 문서](../../../../code/docs/integrator_switch_trial.md)를 따른다.

`check_integrator_switch.py`의 작은 GPU fixture는 Newmark 선택, Gauss 원상 복원 재계산과 직접 Gauss 대조, 최종 실패 시 checkpoint 보존, CPU consistent mass norm 대조, 개별 step 내부 host 조회 금지를 통과했다. 생성한 세 솔버의 graph host copy/callback은0이며 각 dt 객체는 합산 scratch를 독립 소유한다.

`check_integrator_switch_continuation.py`도 통과했다. 외력이 달라지는 연속 프레임에서 Newmark→Gauss→Newmark로 바꾸고 각 전달 상태의 직접 재계산과 대조했다. 솔버를 바꾸는 첫 단계에서 가속도/행렬/초기 힘 캐시를 잘못 이어 쓰는 문제를 확인하는 작은 검증이며 장기 실제 씬 완주와 구분한다.

## 실제 전환과 정확도 결과

| 비교 상태 | Newmark64·128 원래 물리 검산 | 시간 지표 최대 비율: 위치/속도 | 전환 선택, 각2회 |
|---|---|---:|---|
| 초기 처짐 |모두 통과|1.939 / 37.948|모두 Gauss|
| 바람2초 |모두 통과|0.249 / 711.142|모두 Gauss|

시간 지표의 비율1 이하여야 Newmark64를 채택한다. 기하·힘·갱신식·에너지 검산을 통과하더라도 시간 해상도에 따른 속도 차이가 남았다. 그러므로 기하 경고만으로 적분기를 전환하는 방식은 이번 오차를 검출하지 못한다.

각 방법의 전체 프레임 궤적을 같은 반복의 Gauss 단독과 대조한 결과다. Newmark64는 공통65시각,128은129시각에서 비교하며 질량--시간 상대 norm을 사용한다. 반복 두 번의 차이는 아래 표시 자릿수보다 작았다.

작은 위치 차이를 작은 순간 속도 오차로 해석하지 않는다. 초기 처짐은 실제 움직임이 작아 상대 오차가 커 보이는 측면이 있지만, 입력 크기로 정규화한 응답 학습에서 이를 자동으로 무시할 근거는 아니다. 위 수치는 같은 dt의 Gauss 참조와의 차이이며 정확한 시간 연속 해의 오차는 아니다.

재계산 후 끝점은 직접 Gauss와 위치 최대2.146e-17m, 속도 최대1.303e-12m/s 차이였다. 모든 시도의 시작 raw hi/lo가 원본과 정확히 일치했으며, 잘못된 Newmark 끝점에서 Gauss를 이어 계산하지 않았음을 원시 기록으로 확인했다.

## 전환 임계값 민감도와 채택 범위

저장된 지표에 상대0.01%/0.1%/1%, 속도 절대1e-8/1e-7/1e-6m/s를 대입한9조건의 사후 민감도를 보존했다. 위치 절대 지표는1e-10m로 고정했다. 초기 처짐은 **상대1%+속도 절대1e-6m/s** 조건에서만 Newmark 선택으로 바뀌었고, 바람은 모두 Gauss를 선택했다.

이 결과는 그 임계값으로 연속 시뮬레이션을 수행했거나 학습용으로 승인했다는 뜻이 아니다. 위 초기 처짐 Newmark의 실제 Gauss 대비 속도 상대 차이3.15%는 그대로이며, 절대항 덕분에 지표를 통과하는 것이다. Mass RMS 지표는 모든 정점의 최대 오차 상한도 아니다. 작은 절대 차이를 어느 학습 label까지 허용할지는 별도 정확도 예산 결정이 필요하다.

현재 판정은 **전환 구현과 국소 검증 완료, 가속 후보 기본 채택 보류**다. 다른 시점에서 Newmark를 충분히 자주 채택하는지, 그 오차가 장기 궤적과 학습에 허용되는지는 확인하지 않았다. 연속 생성기·체류/재진입 정책·셀프컬리전·시간/공간 수렴·teacher 적격성은 미완료이며 R1 Gate와 기존 기본값을 유지한다.

## 분모와 보존 근거

- 두 고유 저장 상태×두 실행 방식×두 반복으로 프레임 평가8회다. 전환4회 모두 Gauss를 선택했다. 이는8개의 서로 다른 시뮬레이션 구간이 아니다.
- 모든 Newmark trial과 Gauss 대조/재계산을 합쳐16개 trace, 반복을 포함한4864개 계산/검산 단계의 실패 flag가0이었다. warmup과 두 작은 fixture는 이 분모에 넣지 않는다.
- `verification.json`은 완료 단계 수,16개 trace의 원본 시작 hi/lo 일치와 원래 검산 flag0을 확인한다. `analysis.json`은 시각을 맞춘 궤적/끝점 차이와 사후 임계값 민감도를 소유한다.
- 읽기용 compact evidence는 [integrator_switch_trial.json](integrator_switch_trial.json), 소스/원본/결과 hash는 artifact의 `manifest.json`, `evidence_manifest.json`을 따른다. 실제 준비/실행 wrapper도 artifact에 보존한다. 재사용 준비 도구는 `code/scripts/prepare_integrator_switch_trial.py`이며 항상 새 출력 경로를 사용한다.
