# FP32 변형률 식 재작성과 선택적 보정

## 현재 상태

2026-09-13. 같은 물리식의 변형률 재작성과 FP32 보정 후보를 구현·검증했다.
굽힘1/100 손수건·초기 평면/속도0·기존 바람·dt=1/3840초·10프레임/640단계 조건이다.
기준, 식 재작성, 최종 보정의 네 정밀도 경로는 모두 완료했다. 중간 법선/계수 보정은 동일 상태 대조만 수행했다.
**힘 계산 정확도는 개선됐지만 기존 엄격 기준·학습 적격성·가속 채택은 미완료**다.
설정·입력/runtime manifest·원시 결과 검증 수와 상세 수치는 [선별 근거](stable_strain_evidence.json)를 따른다.

## 구현 범위

- `legacy`: 기존 평가식. 기존 기본값과 동결 실행을 보존한다.
- `stable`: 직교 rest tangent T와 변위 기울기 D로 E=sym(TᵀD)+DᵀD/2를 계산한다. 유한 회전의 이차항을 유지한다.
- `stable_normal_pair`: 위 식과 함께 법선 정규화·법선 차분을 FP32 쌍으로 계산한다.
- `stable_geometry_pair`: 위 보정에 G/H 기하 미분 계수의 FP32 변환 잔여 저장과 기하 쌍 누적을 추가한다.
- `stable_metric_pair`: 기하의 low를 변형률 계산까지 전달하고 해당 내적·합산도 보정한다.

새 선택은 FP32 두 경로의 동결 runtime에만 적용한다. FP64 두 기준·기본 솔버 파일·물성·바람·dt·허용오차는 보존한다.
CPU 전처리는 공통 FP64다. GPU의 보정은 두 FP32를 사용하며 FP64 GPU 연산을 도입하지 않았다.
`fp32`는 상태 low=0을 유지하지만 최종 후보의 일부 내부 기하 연산은 FP32 쌍이다. 무보정 단일값 FP32와 구분한다.
HVP·질량·GMRES·cuDSS·행렬 조립은 기존 FP32 경로이며 전체 연산의 확장 정밀도를 보장하지 않는다.
힘·에너지에는 같은 변형률 식을 사용하고 HVP의 방향 미분에도 재작성 식을 연결한다. 유한 정밀도의 HVP와 힘 기하 평가 수준은 다르다.

G/H low 버퍼는 초기화 시 `_Batch`가 소유한다. 새 graph 구성 전에 초기화하고 graph 사용 동안 유지한다.
새 런타임에서 별도 graph를 구성하며 기존 GPU 상주·병렬 합산·current 우선·평가 재사용·무압축/프레임 동기화를 유지한다.
시뮬레이션 중 새로운 CPU 수치 조회를 넣지 않았다. 전체 graph host-node 감사는 이번 검증에 포함하지 않았다.

## 같은 상태에서 원인 분리

기존 FP64/hi-lo 결과의 frame 0/1/5/9 끝 상태를 모든 후보에 동일하게 전달했다.
독립 CPU FP64/longdouble 계산과 GPU 힘·에너지·HVP를 대조했다. 아래는 마지막 상태의 자유 DOF 힘 오차 norm이다.

| 평가 방식 | FP32/hi-lo 상태 | 단일 FP32 상태 |
| --- | ---: | ---: |
| 기존 식 | 2.914e-4 N | 2.914e-4 N |
| 식 재작성 | 2.802e-8 N | 5.397e-7 N |
| + 법선 보정 | 2.688e-08 N | 5.395e-07 N |
| + 기하 계수 보정 | 4.507e-09 N | 5.364e-07 N |
| + 변형률 보정 | 2.856e-09 N | 5.364e-07 N |

단일 FP32 상태를 독립 고정밀 코드로만 평가해도 입력 반올림으로 5.363e-7 N 차이가 생겼다.
이 조건에서는 계산식 보정만으로 상태에 이미 생긴 양자화 오차를 없앨 수 없다.
FP32/hi-lo는 상태 반올림에 의한 차이가 3.824e-14 N으로 작아 기하·힘 연산 보정의 효과가 드러났다.

법선 보정만으로는 마지막 상태 오차 감소가 약4%였다. 같은 상태에서 G/H 계수만 FP32로 바꾼 CPU 진단은
G 2.516e-8 N, H 4.073e-9 N, G/H 함께 2.639e-8 N의 차이를 보여 계수 변환을 후속 보정 대상으로 정했다.
이는 각 원인의 완전한 가산 분해가 아니다. 최종 동일 상태의 volume/edge 오차는 선별 근거에 별도로 남긴다.

## 10프레임 실행 결과

독립 힘 잔차는 각 프레임 마지막 후보10개 중 최대다. 경고는 전체640단계에서 집계했다.
동일 상태의 힘 평가 오차와, 서로 다른 궤적에서 얻은 운동방정식 잔차를 구분한다.

| 경로 | 기존 잔차 최대 | 식 재작성 | 최종 보정 | 경고 단계: 기존→식→보정 |
| --- | ---: | ---: | ---: | --- |
| FP32/hi-lo | 2.525e-4 N | 2.845e-8 N | **2.531e-9 N** | 573→437→430 |
| 단일 FP32 상태 | 2.526e-4 N | 1.408e-7 N | 1.291e-7 N | 573→553→551 |

FP32/hi-lo의 표본 최대 잔차는 약10만 배 개선됐지만 최종 기준 초과 배율은 약25.1이다.
최종 경고 코드1/2/3/7/8 횟수는 각각65/149/206/72/0이다. 중복 경고가 가능하다.
선형 반복 누계는 기준2,886, FP32/hi-lo26,722다. 선형 미수렴·힘 잔차·행렬 일치 검사가 남았다.
GMRES 목표는 고정1e-10이 아니라 설정 floor1e-10와 cap1e-4 사이의 적응 값이다.
독립 재평가 상대잔차만으로 이 적응 종료 판정을 대신하지 않는다.

최종 FP32/hi-lo의 기준 대비 전체 최대 위치 성분 차이는8.490µm로 기존8.493µm와 비슷하다.
면적 가중 위치 RMS 최대도1.262µm로 비슷하다. 속도 RMS 최대는48.48→27.10µm/s로 줄었으나,
힘 잔차 감소가 궤적 전체의 비례 개선으로 이어지지는 않았다.
표본 에너지 장부 잔차 최대는 약8.27e-11 J로 개선이 확인되지 않았다. 표본 고정점 이탈은0이다.
최종 운동/탄성 에너지·변형률 수치는 선별 근거에 포함했다. 0.167초 결과를 장기 안정성으로 일반화하지 않는다.

최종 생성·기록 시간은 FP64/hi-lo11.98초, FP64 9.94초, FP32/hi-lo57.30초, 단일 FP32 상태53.82초다.
같은 GTX1080Ti에서 순차 실행했고 매 프레임 동기화·추가 진단 기록을 포함한다. 초기화·전송/저장·독립 분석은 제외한다.
기존 실행의 FP64/hi-lo42.92초와 이번 재실행11.98초가 달라 실행 간 시간비를 알고리즘 가속률로 해석하지 않는다.
장치 부하·클록을 통제한 벤치마크는 아니며, 최종 실행 안에서도 FP32가 FP64보다 빨라지지 않았다.

## 검증과 재현

- 기존 정책 CPU 검사9개, 변형률 식/유한 회전/방향 미분/소스 계약 검사4개, 실제 Warp CPU 보정 산술 검사2개 통과.
- 동일 저장 상태4개와1.7rad 회전 입력에서 GPU HVP 상대오차는 검사 기준1e-5 이내다.
- 회전 입력은 고정 경계 모델의 같은 입력 대조이며, 경계까지 자유롭게 회전시킨 무응력 시험이 아니다.
- 기본/식 재작성/최종 보정은 네 경로 모두640단계, 독립 분석 오류0. 원시 결과40개씩과 각 입력 manifest를 해시 대조했다.
- 기존 및 새 결과를 덮어쓰지 않았다. 생성된 runtime은 source manifest로 구분한다.

재현은 **새 출력 경로**에서 수행한다. 아래 명령은 준비만 수행한다.

```bash
bash experiments/R1_teacher_velocity_reset/timestep_search/run_precision_compare.sh \
  --out experiments/artifacts/runs/teacher_precision_compare/strain_corrected_new \
  --strain-formula stable_metric_pair --frames 10 --prepare-only
```

실행은 같은 `--out`으로 `--run-prepared`를 사용한다. 최종 확인 결과는
`artifacts/runs/teacher_precision_compare/20260913_stable_metric_pair_v2`에 있다.
`20260913_stable_normal_pair_v1`, `20260913_stable_geometry_pair_v1`은 전체 궤적을 실행하지 않은 중간 대조다.

다음 검토 대상은 남은 행렬/선형 풀이 오차와 에너지·궤적 차이다. 이번 작업에서는 허용오차 완화,
FP64 잔차 보정, 셀프 컬리전, 바람 변경이나 학습 발행을 수행하지 않았다.
