# 2026-05-06 M01 static 3DGS I/O

## Context

M1을 real/pretrained 3DGS asset 없이 시작하기 위해 synthetic/minimal 3DGS asset과 static rendering pipeline을 먼저 구현했다. 사용자는 local 환경에서 `gsplat==1.5.3`, `torch.cuda.is_available() == True`, `gsplat.rendering.rasterization` import 성공을 확인했다.

## Decisions

- M01 experiment folder는 `experiments/M01_static_3dgs_io/`를 사용한다.
- Synthetic asset은 leaf-like thin sheet 형태의 Inria-style 3DGS `.ply`로 생성한다.
- Loader는 `.ply`의 `mean`, `scale`, `rotation`, `opacity`, `SH coefficients`를 직접 읽고 runtime value로 변환한다.
- Camera JSON은 `world-to-camera, +z forward` convention을 명시한다.
- Renderer entrypoint는 `--backend auto|gsplat|cpu_debug`를 지원한다.
- `auto`는 `gsplat` CUDA rasterization을 먼저 시도하고, 실패하면 CPU debug preview로 fallback한다.
- `torch.cuda.is_available() == True`와 `gsplat.rendering.rasterization` import 성공만으로는 충분하지 않다. `gsplat` CUDA extension `_C`가 load되어야 actual rasterization이 가능하다.

## Current Blocker

agent 실행 환경에서는 `gsplat: No CUDA toolkit found. gsplat will be disabled.` 상태를 확인했다. 사용자 local shell에서는 CUDA Toolkit 12.6과 `nvcc`를 설정한 뒤 `gsplat` JIT build가 시작되었지만, build target이 `compute_61` / `sm_61`로 잡히면서 `cooperative_groups::labeled_partition` compile error가 발생했다.

`check_gsplat_env.py` 결과 사용자 local GPU는 `NVIDIA GeForce GTX 1080 Ti`, Compute Capability `6.1`로 확인되었다. NVIDIA CUDA docs 기준 `labeled_partition`은 Compute Capability 7.0 이상이 필요하다. 따라서 `gsplat 1.5.3` CUDA backend는 이 machine에서 사용할 수 없을 가능성이 높다.

다음 명령이 성공해야 system-level blocker가 풀린다.

```bash
.venv/bin/python experiments/M01_static_3dgs_io/scripts/render_static_baseline.py --backend gsplat
```
